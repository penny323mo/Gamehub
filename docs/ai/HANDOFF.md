### Elden Ring II：套件慢到開始判錯冇壞嘅嘢 (ADR-186)

- 套件跑到成半個鐘之後，**唔止係慢**：一次跑手機版塊等入場掣等 60 秒 timeout 直接掛咗，另一次讀到兩條
  紅 gate 而佢哋啲碼冇問題。**慢變咗判錯**。
- 「邊條慢」本來冇尺——`ER2_TIME=1` 而家印每條之間用咗幾秒＋尾段一個 top-10。量完即刻有回報：我原本估
  係啲 `waitForTimeout`，但佢哋加埋先八分鐘。兩個真成因都係結構性：
  - **兩個版塊喺主 page 泊低之前跑**。主 page 係一個仲行緊嘅 WebGL loop，軟件光柵化之下食晒 CPU；泊嗰
    行嘅註釋一早寫咗呢個坑，而佢**上面**有兩個版塊正正就係咁做緊。兩個都自足，搬落去就算。→ **955 秒**。
  - **解析度就係幀率，而幀率就係遊戲時間**（`delta` 封喺 0.05）。實測同一部機 640×380 **1.7 fps**、
    420×250 **3.2**、320×190 **4.2**。啲量度頁一條都唔關解析度事（量郁動秒同計數器），所以改用
    320×190；版位／鏡頭／觸控嗰啲照用真尺寸，因為佢哋量緊嘅就係尺寸。→ **637 秒**（boss 場 174 → 63、
    重開 131 → 60）。
- **我自己兩條 gate 問錯咗問題，負載一大就露底**：手機衝刺嗰條同時要求速度同 `Run*` 動畫——速度過 4.4
  本身已經係證明（行路路徑數學上去唔到），而動畫係抽樣嗰刻嘅瞬時狀態，一次啱好讀到 `RecieveHit`，
  6.82 米／秒照樣判紅。鏡頭收位嗰條寫「尾段中位 < 0.02」，個數係由一次量到嘅 0.004 拍出嚟；有次讀到
  0.025 而條尾段係 0.028 → 0.016，**明明喺度收斂都判咗紅**。突變嘅特徵係**永遠唔收**（0.03–0.16 遊走）。
  改成問「尾段有冇一路細落去」之後**又紅多一次**，讀到 `[0,0,0,0,0,0]`——**收到盡就唔再細落去**。

### 上一輪：Penny 報「畫面一直抖動」(ADR-185)

- ADR-177 果次用截圖查、重現唔到：**一個逐幀嘅現象唔可以用 2.4 赫茲抽樣**。今次用逐幀嘅場內尺，仍然重
  現唔到，但揾到兩個真缺陷。**我攞到嘅第一個數係我自己支尺錯**：`allowed` 睇落「企定一幀跳 8.2 米」，
  其實係 reset 冇清上一幀個值；修返之後企定跳 **0.021**、鏡頭 **0.012** 中位——**鏡頭係穩定嘅**。
- **renderer 同 composer 用兩個唔同像素比**（1.8 對 1.55）：dpr ≤ 1.55 兩個一樣，所以**喺測試機同普通
  螢幕必然睇唔到**，條 gate 一定要喺 `deviceScaleFactor: 3` 度跑。高 dpr 即係**逐幀非整數重採樣**。
- **震動寫咗入平滑狀態**（`camera.position` 就係 lerp 個狀態）：修前**永遠收唔到**（0.03–0.16 遊走），
  修後收斂到 **0.004**。**未證實**兩個係咪 Penny 見嗰個；仲抖嘅話最有用係邊部機、選單度抖唔抖。
