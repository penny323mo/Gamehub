  `else if (bossDistance > BOSS_REACH)` 之後——只有 ≤ **3.15** 先入到去。個純函數有 gate 而且綠，因為條
  gate 直接餵遊戲從來唔會餵嘅距離（同 ADR-179 個 `locked` 一樣）。**同一道門仲有第二把鎖**：實測換第二
  階段嗰刻距離係 **6.0 米**，已經細過 6.5——埋身手段淨係喺埋咗身之後先開放，等於冇。兩個階段而家都撲
  得（二階密好多）＋ 加咗 `LEAP_MAX_RANGE`。
- **每一下命中都取消緊 boss 出緊嗰招**（`state = "hit"` 無條件蓋過前搖）：實測射手打到 boss 剩 **17 血，
  出手 1 次、到落點 0 次**——個預警圈變咗裝飾。而家有霸體：**出手 4、落點 4、打出 132 傷害**，撲擊出到。
- 條規則搬咗去 `src/boss.ts`（`.tsx` 喺 `--experimental-strip-types` 下 import 唔到，即係住喺
  `GameClient.tsx` 嘅規則**淨係得瀏覽器測到**）。新 Node test 問瀏覽器答唔到嗰樣：窗口同 caller 夾唔夾。
- **三條舊 gate 變紅，兩條本來綠得唔啱理由**：兩條 bossMove gate 用 `LEAP_MIN + 8`（14.5 米）自己砌個
  「遠」出嚟，加咗上限之後跌咗出窗口——**支尺自己砌條規則嘅輸入就會跟唔上條規則**（而家問 `leapRange()`
  攞窗口）。而**我上一輪嗰條 boss 重開 gate，一直靠八隻唔應該存在嘅雜兵打死玩家先綠**——`推關()` 一修好

### 上一輪：支模擬搖桿其實係數位嘅，而一半玩家跑唔到步 (ADR-183)

- `updateStick` 算咗個幅度出嚟，跟住一行 `movement.normalize()` 即刻掉咗佢——**輕推同推到底一樣快**，
  觸控上面根本冇「慢行」。修完半推 ＝ **2.2 米／秒 ＋ Walk**。而**衝刺淨係綁 `ShiftLeft`**（觸控得三粒
  掣），即係成個 1.55 倍嘅機制手機玩家一世用唔到。加第四粒掣係錯答案（ADR-175 為咗掣位打過一場）；
  主機做法零 UI 成本——**推到個環度就係跑**（0.97）。鍵盤由結構上唔受影響：佢個幅度永遠係 1，而衝刺
  門檻讀嘅係**另一個**淨係觸控嗰個幅度（讀埋鍵盤就變成撳 W ＝ 衝刺）。
- **一條我自己揀得太貼嘅線**：第一版寫「衝刺 > 設計速 × 1.05」，實測 4.8 對 4.62。而行路嗰條路嘅目標係
  `設計速 × 推度`、推度上限 1，即係**行路數學上唔可能過 4.4**——條線改成「高過 4.4」，非黑即白。半推
  嗰條就對住條規則自己嘅預測值（2.2 對 2.2）。
